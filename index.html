# Science.nu–style site — Quick starter + deployment guide ## What you'll get - A minimal, calm, readable HTML/CSS starter that mimics the simple, academic look of sites like science.nu - Exact files: `index.html`, `styles.css`, sample posts and a Jekyll example - Step-by-step Git/GitHub commands to publish with GitHub Pages (user site or project site) --- ## Prerequisites - Git and a GitHub account - Basic comfort with HTML/CSS and the command line - (Optional) Ruby & Jekyll only if you choose the Jekyll route --- ## Deployment options (pick one) 1. **User/Organization site** — repository named `YOURUSERNAME.github.io`. Put `index.html` at repo root and push to `main`. The site will be served at `https://YOURUSERNAME.github.io`. 2. **Project site** — a normal repo. Use the `gh-pages` branch or the `docs/` folder on `main` and enable Pages in repo settings. 3. **Jekyll-powered site** — use Jekyll if you want Markdown posts, templating and front matter. GitHub Pages supports Jekyll with minimal setup. (Examples for each are below.) --- ## File: index.html ```html Science — Short essays on data & methods

Put `index.html` at the repository root. --- ## Project site (alternative) - Create any repo (e.g., `notes`) and push your site into the `gh-pages` branch, or push to `main` and put the site under `docs/` and set the publishing source in Settings → Pages → Deploy from a branch → `main` / `docs/`. - If you're using a static site generator or build step, commit the generated `site/` output to the `gh-pages` branch (or use GitHub Actions to build and deploy). --- ## Optional: Jekyll (Markdown + templates) If you want blog-post style authoring in Markdown and automatic index pages, use Jekyll. Minimal example files: `_config.yml` ```yaml title: Science baseurl: "" # or "/repo-name" for project sites ``` `_posts/2025-10-03-welcome.md` ```markdown --- layout: post title: "Welcome" --- This is a sample post using Jekyll front matter. ``` Jekyll will turn Markdown posts into HTML. See GitHub Pages docs for details on supported plugins and local testing (`jekyll serve`). --- ## Custom domain & HTTPS - To use a custom domain add a `CNAME` file with your domain in the repo root and configure DNS (A and/or CNAME records) as GitHub Docs describe. - Enable HTTPS in your repository Pages settings once the domain is configured. --- ## Testing locally (simple) If you don't use Jekyll, you can preview the static files with Python's built-in server: ```bash python -m http.server 8000 # then open http://localhost:8000 ``` If you're using Jekyll, use `bundle exec jekyll serve` (after installing dependencies). --- ## Extra suggestions / next steps - Add an `RSS` feed (simple XML) and a small search (client-side, e.g. fuse.js) if you want search. - Add an accessibility pass: semantic headings, `lang` attribute (already set), and visible focus outlines. - Consider adding a small `README.md` with author info and instructions for contributing. - Optionally add GitHub Actions to build (if you have a build step) and push to `gh-pages`. --- ## Troubleshooting & tips - If you want to bypass Jekyll (e.g., to serve files that start with `_`), add an empty `.nojekyll` file. - If Pages doesn't reflect your latest push, double-check the publishing source in the repo's Pages settings and that you pushed to the configured branch. --- Happy building — open the files above, copy them into a repository, and you're set. Tweak typography, spacing, and colors to match the exact look you want.
